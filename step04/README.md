## 1. 指针数组 vs 二维数组 — 存储字符串列表

### 问题

我们需要存储一组命令名称：`"echo"`, `"type"`, `"exit"`, `"pwd"`, `"cd"`。

### 方案 A：二维数组

```c
char builtins[][5] = {"echo", "type", "exit", "pwd", "cd"};
```

**内存布局：** 每个字符串必须占用相同的宽度（最长的 + 1 = 5 字节）：

```
┌───┬───┬───┬───┬───┐
│ e │ c │ h │ o │\0 │  ← 第0行，5字节
├───┼───┼───┼───┼───┤
│ t │ y │ p │ e │\0 │  ← 第1行，5字节
├───┼───┼───┼───┼───┤
│ e │ x │ i │ t │\0 │  ← 第2行，5字节
├───┼───┼───┼───┼───┤
│ p │ w │ d │\0 │   │  ← 第3行，浪费2字节！
├───┼───┼───┼───┼───┤
│ c │ d │\0 │   │   │  ← 第4行，浪费3字节！
└───┴───┴───┴───┴───┘
```

缺点：固定的列宽导致"pwd"和"cd"会浪费空间。如果以后要加"export"（6字节），必须把 `[5]` 改成 `[7]`，牵一发动全身。

### 方案 B：指针数组（代码中的做法）

```c
char *builtins[] = {"echo", "type", "exit", "pwd", "cd", NULL};
```

**内存布局：** 每个元素只是一个 8 字节的指针，指向任意长度的字符串：

```
 builtins 数组（连续存放指针）
┌───────────┐        ┌───┬───┬───┬───┬───┐
│ 0x1000 ───┼──────> │ e │ c │ h │ o │\0 │  (5字节，刚好)
├───────────┤        └───┴───┴───┴───┴───┘
│ 0x2000 ───┼──┐     ┌───┬───┬───┬───┬───┐
├───────────┤  └───> │ t │ y │ p │ e │\0 │  (5字节，刚好)
│ 0x3000 ───┼──┐     └───┴───┴───┴───┴───┘
├───────────┤  │     ┌───┬───┬───┬───┬───┐
│ 0x4000 ───┼──┤ ──> │ e │ x │ i │ t │\0 │  (5字节，刚好)
├───────────┤  │     └───┴───┴───┴───┴───┘
│ 0x5000 ───┼──┤     ┌───┬───┬───┬───┐
├───────────┤  │     │ p │ w │ d │\0 │  (4字节，不浪费)
│ NULL      │  │     └───┴───┴───┴───┘
└───────────┘  │     ┌───┬───┬───┐
               └───> │ c │ d │\0 │  (3字节，不浪费)
                     └───┴───┴───┘
```

### 遍历方式

末尾放一个 `NULL` 作为**哨兵值**，就像高速公路上的"终点"标志：

```c
for (i = 0; builtins[i] != NULL; i++) {
    if (strcmp(cmd, builtins[i]) == 0) {
        return 1;  // 找到了！
    }
}
return 0;  // 遍历完都没找到
```

**生活中类比：** 二维数组就像一个表格，所有格子大小固定；指针数组就像名片夹，每张名片（字符串）长度不同，但夹子本身（指针）大小一样。

## 2. strtok — "幽灵般"的分割函数

### 它在做什么？

把一条路径字符串按 `:` 分割成多个目录：

```c
char* path = "usr/bin:/usr/local/bin:/bin";
char* dir = strtok(path, ":");
// dir = "usr/bin"  (第一个token)
```

### strtok 的三个诡异特性

#### 诡异 1：它会修改原字符串

```c
char str[] = "A:B:C";
char* token = strtok(str, ":");

// str 现在变成了： "A\0B\0C"
//                    ↑  ↑
//                  strtok 把冒号全部替换成了 \0（字符串结束符）
```

所以代码中要用 `strdup(path_env)` 先复制一份，**不能直接传 `getenv("PATH")` 的返回值**，因为环境变量的内存是只读的，修改它会崩溃。

#### 诡异 2：第二次调用要传 NULL

```c
char* first  = strtok(str, ":");     // 传原字符串，得到 "A"
char* second = strtok(NULL, ":");    // 传 NULL，得到 "B"
char* third  = strtok(NULL, ":");    // 传 NULL，得到 "C"
char* fourth = strtok(NULL, ":");    // 传 NULL，返回 NULL（没有了）
```

**为什么会这样？** `strtok` 内部有一个**隐藏的静态变量**记住了上次解析到哪里。传 `NULL` 就是在告诉它："继续从上次停下的地方往后走"。

#### 诡异 3：strtok 不可重入（not reentrant）

因为它用内部静态变量存状态，如果你在循环 A 里调用它，又在一个信号处理函数里也调用它，它们会互相干扰。

**更安全的版本：** `strtok_r(str, ":", &save_ptr)`，所有状态存在开发者提供的 `save_ptr` 里。

### 代码中的完整流程

```c
char* path_copy = strdup("/usr/bin:/bin");  // ← 先复制
char* dir = strtok(path_copy, ":");          // 第1次：得到 "/usr/bin"
while (dir != NULL) {
    snprintf(full_path, sizeof(full_path), "%s/%s", dir, cmd);
    // 拼接成 "/usr/bin/ls"
    if (access(full_path, X_OK) == 0) {
        // X_OK 检查文件是否可执行（不只是是否存在！）
        return full_path;  // 找到了！
    }
    dir = strtok(NULL, ":");                 // 继续：得到 "/bin"
}
free(path_copy);  // ← 别忘了释放！
```

## 3. static 缓冲区 — "活了很久"的局部变量

### 问题

看这段代码：

```c
char* find_in_path(const char* cmd) {
    static char full_path[MAX_INPUT];   // ← 注意 static
    // ...
    snprintf(full_path, sizeof(full_path), "%s/%s", dir, cmd);
    return full_path;                    // ← 返回局部变量？
}
```

### 为什么不能直接 `char full_path[MAX_INPUT]`（不加 static）？

```c
// ❌ 错误写法
char* bad_function() {
    char result[100];  // 普通局部变量，放在"栈"上
    strcpy(result, "hello");
    return result;     // 危险！
}  // ← 函数结束，result 所在的内存被回收（栈帧销毁）

int main() {
    char* p = bad_function();
    printf("%s", p);   // 未定义行为！可能打印乱码，可能崩溃
}
```

**生活类比：** 普通局部变量就像租的酒店房间，退房后你不能继续使用。`static` 变量像买下来的房子，一直属于你。

### static 的工作原理

```
普通变量（栈）:                static 变量（全局数据区）:
┌─────────────┐               ┌─────────────┐
│  函数调用时  │               │  程序启动时  │
│  分配空间    │               │  分配空间    │
├─────────────┤               ├─────────────┤
│  函数返回时  │               │  整个程序    │
│  空间回收 ❌  │               │  运行期间    │
│             │               │  始终存在 ✅  │
└─────────────┘               └─────────────┘
```

### static 的副作用（重要！）

```c
char* a = find_in_path("ls");
char* b = find_in_path("gcc");
// a 和 b 指向的是同一块 static 内存！
// b 中存放的是 "/usr/bin/gcc"
// 此时 a 里的内容也被覆盖成了 "/usr/bin/gcc"！
```

这就是代码注释里说的："调用者必须立即使用返回值，否则会被下一次调用覆盖"。

## 4. fork() + execvp() — Shell 的灵魂（最核心难点）

这是整个 Shell 程序**最最重要、最难理解**的部分。让我们一步步拆解。

### 4.1 背景：execvp 会"自杀"

```c
int main() {
    printf("Shell 启动\n");
    execvp("/bin/ls", args);  // ← 用 ls 程序替换当前进程
    printf("这行永远不会执行！\n");
}
```

`execvp` 做的事情不是"调用一个函数"，而是：

```
调用前:                     调用后:
┌──────────────┐            ┌──────────────┐
│ 当前进程      │  execvp    │ 同一个进程    │
│              │  ═══════>  │              │
│ 代码: Shell  │            │ 代码: ls     │
│ 数据: ...    │            │ 数据: ls的   │
│ 堆栈: ...    │            │ 堆栈: ls的   │
└──────────────┘            └──────────────┘
  进程ID不变                 进程ID还是那个
  Shell 的代码没了！         完全变成了 ls 程序
```

**就像把一本书的内容全部擦掉，换成另一本书的内容。** Shell 自己就被"擦掉"了。

### 4.2 解决方案：fork() 创造分身

```c
pid_t pid = fork();  // ← 关键！创建一个子进程

if (pid == 0) {
    // === 子进程（分身） ===
    execvp(exec_path, argv);  // 只替换分身，本体没事
} else {
    // === 父进程（本体/Shell） ===
    waitpid(pid, &status, 0);  // 等分身干完活
}
```

### 4.3 fork() 的魔法："一次调用，两次返回"

这是初学者最困惑的地方：

```c
printf("fork 之前\n");

pid_t pid = fork();  // ← 一个函数调用

// ══════ 从这里开始，代码在"两个进程"中同时运行 ══════

printf("fork 之后，pid = %d\n", pid);
```

**运行结果：**
```
fork 之前
fork 之后，pid = 12345    ← 来自父进程
fork 之后，pid = 0        ← 来自子进程
```

**图解：**

```
         main() 进程 (PID=100)
              │
              │  fork()
              │
    ┌─────────┴─────────┐
    │                   │
 父进程 (PID=100)      子进程 (PID=12345)
 fork() 返回 12345     fork() 返回 0
    │                   │
    │ 走 else 分支       │ 走 if(pid==0) 分支
    │ waitpid(...)       │ execvp(...)
    │ 继续 Shell 循环    │ 变成 ls 程序
```

**生活类比：** fork 就像游戏里的"影分身术"——你（父进程）站在原地，同时出现一个一模一样的分身（子进程）。分身去做危险任务（execvp 替换自己），本体安全等待。`fork()` 返回值就是你的"通信手环"：分身的手环显示 0（知道自己是分身），本体的手环显示分身的编号。

### 4.4 waitpid — "等分身回来"

```c
waitpid(pid, &status, 0);  // 父进程在这里"阻塞等待"
```

- **阻塞**：父进程暂停执行，直到子进程结束。
- **为什么需要？** 如果不等，按下回车后可能新提示符 `$` 和 `ls` 的输出混在一起，变成：

```
$ $ ls
Desktop  Documents  Downloads
```

有了 `waitpid` 后才是正常的：

```
$ ls
Desktop  Documents  Downloads
$
```

### 4.5 完整执行流程举例

用户输入：`ls -l /home`

```
1. 解析命令: cmd_name="ls", args="-l /home"

2. find_in_path("ls")
   → 搜索 PATH: /usr/bin, /bin, ...
   → 找到 "/bin/ls"

3. 构建 argv: ["ls", "-l", "/home", NULL]

4. fork() ─→ 创建子进程
   │
   ├─ 子进程(pid==0):
   │    execvp("/bin/ls", argv)
   │    → 当前进程变成 ls 程序
   │    → 执行 ls -l /home
   │    → ls 执行完毕，子进程结束
   │
   └─ 父进程(pid>0):
        waitpid(pid, &status, 0)
        → 等待子进程结束
        → 子进程结束，继续 Shell 主循环
        → 打印 "$ " 等待下一条命令
```

## 5. cd 为什么必须是内置命令

### 错误的想法

如果我们把 cd 当成外部命令，用 fork+exec 执行：

```c
// ❌ 这样不行！
if (strcmp(cmd_name, "cd") == 0) {
    exec_command(cmd_name, args);  // fork 子进程执行 cd
}
```

### 为什么不行？

```
父进程 (Shell, PID=100)          子进程 (PID=12345)
CWD = /home/user                 CWD = /home/user (fork 后也一样)
    │                                │
    │  等待子进程...                  │  chdir("/tmp")
    │                                │  CWD = /tmp  ← 子进程改了！
    │                                │
    │  子进程结束 ←────────────────  │  子进程退出
    │                                X  进程消失
    │
CWD = /home/user  ← 没变！！！
```

**核心原理：** 每个进程有自己的"当前工作目录"（Current Working Directory, CWD）。子进程改了自己的 CWD，不影响父进程。就像你克隆了一个自己，克隆人去了一趟图书馆，不代表你本人也去了图书馆。

### 正确做法

```c
// ✅ 直接在当前进程（Shell）中修改
if (strcmp(cmd_name, "cd") == 0) {
    chdir(path);  // 直接改变 Shell 进程的工作目录
}
```

这就是为什么 cd 必须是**内置命令（builtin）**——不能 fork 子进程去执行。

> 同理，`exit` 退出 Shell、`export` 设置环境变量，这些也都必须是内置命令。

## 6. 二级指针 — 函数如何修改外部的指针变量

### 问题

我们想写一个函数，既能提取"第一个单词"，又能告诉调用者"剩余部分从哪开始"。

### 普通指针做不到

```c
void extract_word(const char* src, char* dest, const char* rest) {
    // ...提取...
    rest = skip_space(src + i);  // 修改的是局部变量 rest！
}  // 函数结束，rest 的修改丢失了！

// 调用方：
const char* rest;
extract_word(cmd, cmd_name, rest);
// rest 仍然是原来的值，没有变化！
```

**原理：** C 语言函数传参是"值传递"。`rest` 变量在函数内部是一个副本，修改副本不影响原变量。

### 二级指针的解法

```c
void extract_word(const char* src, char* dest, const char** rest) {
    // ...提取 cmd_name ...
    *rest = skip_space(src + i);  // 修改的是 rest 指向的那个指针变量
}

// 调用方：
const char* rest;
extract_word(cmd, cmd_name, &rest);  // 传 rest 的地址
// rest 现在指向 args 了！
```

### 图解

```
调用方:                          extract_word 函数内:
                                 
  rest                           rest (形参) → 是一个二级指针
  ┌───┐                          ┌────────┐
  │ ? │  ← 未初始化               │ 0x2000 │ ──┐
  └───┘                          └────────┘   │
 地址: 0x2000                                 │
  ↑                                           │
  │ &rest = 0x2000                            │
  │                                           │
  │ 传入 &rest                                │
  └───────────────────────────────────────────┘

  *rest = skip_space(...)
  ↓
  修改地址 0x2000 处的内容
  ↓
  rest
  ┌──────────────────┐
  │ 指向 args 的位置  │  ← 修改成功！
  └──────────────────┘
```

**生活类比：**
- 一级指针 `char*`：我告诉你"把书放到桌子上"——直接操作目标。
- 二级指针 `char**`：我告诉你"桌子在哪里"——你通过地址找到了桌子，再在桌子上操作。

**万能记忆法则：** 如果要在函数内修改某个变量 `X`，就需要传 `&X`。
- 修改 `int` → 传 `int*`
- 修改 `int*` → 传 `int**`
- 修改 `int**` → 传 `int***`（别写这么深的...）

## 7. 代码中的潜在 Bug

### handle_cd 函数的逻辑错误

```c
void handle_cd(const char* path) {
    const char* home_path = skip_space(path);
    if (path == NULL && *path == '\0') {   // ← BUG: 应该是 ||
        // ...
    }
}
```

**问题：** `&&` 表示"且"——必须 path 为 NULL **同时** `*path` 为 `'\0'`。但 `path == NULL` 和 `*path == '\0'` 不可能同时成立：
- 如果 `path == NULL`，`*path` 的解引用是**未定义行为**（可能直接崩溃）。
- 如果 `*path == '\0'`，说明 path 不是 NULL。

**正确写法应该是 `||`（或）：**

```c
if (path == NULL || *path == '\0') {
    // path 为 NULL 或者 path 为空字符串时，跳转到 HOME 目录
    if (home != NULL) {
        if (chdir(home) != 0) {
            printf("cd: %s: No such file or directory\n", home);
        }
    }
    return;
}
```

## 总结：Shell 的核心心智模型

```
┌──────────────────────────────────────────────────────┐
│                    Shell 主循环                        │
│                                                      │
│   ┌──────────┐    ┌──────────┐    ┌───────────────┐  │
│   │ 读取输入  │───>│ 解析命令  │───>│ 判断命令类型   │  │
│   │ fgets()  │    │extract   │    │               │  │
│   └──────────┘    │_word()   │    └───┬───────┬───┘  │
│                   └──────────┘        │       │      │
│                              ┌────────┘       └──────┐│
│                              ▼                       ▼│
│                      ┌──────────────┐    ┌──────────┐│
│                      │ 内置命令      │    │ 外部命令  ││
│                      │ echo/type/   │    │ ls/gcc/  ││
│                      │ pwd/cd/exit  │    │ cat/...  ││
│                      └──────┬───────┘    └────┬─────┘│
│                             │                 │      │
│                             ▼                 ▼      │
│                      ┌──────────────┐    ┌──────────┐│
│                      │ 直接调用函数  │    │ fork()   ││
│                      │ (不改进程)    │    │   ↓      ││
│                      └──────────────┘    │ execvp() ││
│                                          │   ↓      ││
│                                          │waitpid() ││
│                                          └──────────┘│
└──────────────────────────────────────────────────────┘
```

**记住一句话：** 内置命令在 Shell 自己的进程里跑，外部命令 fork 一个分身去跑，等分身跑完了再继续。
